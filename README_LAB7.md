# Лабораторная работа 7

## Готовое приложение

Приложение использует Spring MVC, Thymeleaf, Spring Data JPA, H2 и Actuator. Сохранены Spring Boot 4.1.1 и Java 17 из присланного проекта. В методичке разрешена другая актуальная версия Spring Boot.

Реализованы Student и StudentRepository, StudentController, add-student-form.html и list-students.html. По аналогии добавлены StudyGroup, StudyGroupRepository, StudyGroupController, add-group-form.html и list-groups.html. Для обеих сущностей работают создание, просмотр списка, изменение и удаление.

У студента поля: имя, фамилия, факультет и возраст. У учебной группы: название, факультет, куратор и курс. Поля группы выбраны самостоятельно, так как методичка не задаёт их состав. Для текста и чисел настроены ограничения, ошибки отображаются рядом с полями и не записываются в БД.

Таблицы STUDENTS и STUDY_GROUPS автоматически создаются при первом запуске. Файловая база находится в testdb/students.mv.db. Данные сохраняются после перезапуска, повторный запуск не очищает таблицы. База лабораторной 6 отдельно не используется.

## Запуск

1. Откройте вложенную папку MyUiRestDbService с pom.xml в IntelliJ IDEA. При необходимости нажмите правой кнопкой на pom.xml → Add as Maven Project.
2. Выберите JDK 17. При уведомлении Lombok нажмите Enable annotation processing.
3. Остановите приложение лабораторной 6, если оно занимает порт 8080.
4. Запустите MyUiRestDbServiceApplication кнопкой возле main. Дождитесь сообщения Started MyUiRestDbServiceApplication.
5. Откройте в обычном браузере http://localhost:8080/list — список студентов.
6. Откройте http://localhost:8080/groups — список учебных групп. Между списками также есть ссылки в верхней части страниц.

Нужно только одно приложение. Postman для ввода студентов и групп не требуется: работа выполняется через веб-формы.

Working directory конфигурации запуска должен указывать на папку с pom.xml этого проекта. Именно от неё разрешается относительный путь к testdb.

## Проверка форм

Студенты:

1. На странице /list нажмите «Добавить студента».
2. Заполните имя, фамилию, факультет и возраст. Нажмите «Сохранить».
3. Убедитесь, что строка появилась в списке.
4. Нажмите «Изменить», измените возраст или имя, сохраните и проверьте список.
5. Перезапустите приложение и убедитесь, что запись осталась.
6. Нажмите «Удалить» и убедитесь, что запись исчезла.

Учебные группы:

1. Перейдите в «Учебные группы» и нажмите «Добавить группу».
2. Например, введите РИЗ-250110у, РТФ, Архипов Н.А., курс 2.
3. Сохраните и проверьте строку в списке.
4. Измените курс на 3 и сохраните.
5. Проверьте удаление кнопкой «Удалить».

Добавление и изменение используют одну форму для каждой сущности, как в методичке. Удаление отправляет POST-запрос кнопкой, чтобы простое открытие ссылки не удаляло данные. Перестановка имени и фамилии в HTML-примере методички исправлена: заголовки соответствуют значениям.

## Проверка Actuator

Откройте следующие адреса в браузере или Postman:

1. http://localhost:8080/actuator/health — состояние приложения и подключения к H2, ожидается status=UP.
2. http://localhost:8080/actuator/info — название, описание и версия приложения.
3. http://localhost:8080/actuator/metrics — список доступных метрик.
4. http://localhost:8080/actuator/metrics/jvm.memory.used — использование памяти JVM.
5. http://localhost:8080/actuator/metrics/process.uptime — время работы JVM в секундах.

Также доступны /actuator/mappings и /actuator/beans. Значения метрик меняются во время работы приложения — это ожидаемо.

В папке Lab7_screenshots рядом с README сохранены реальные скриншоты. Файлы 04–08 показывают пять вызовов Actuator и подходят для соответствующего раздела отчёта. Они сняты на тестовом экземпляре с портом 18087; обычный запуск проекта использует 8080. Изображения 01–03 показывают страницы студентов и групп. Данные на снимках тестовые, они не добавляются автоматически в вашу базу.

## Автоматические проверки

Запустите UiIntegrationTest через зелёную кнопку возле класса или Maven → Lifecycle → test. Тесты используют изолированную H2 в памяти, а не пользовательскую файловую базу. Проверяются CRUD студентов и групп, возврат 404 для отсутствующих записей, отказ сохранения неверных полей и пять методов Actuator. Вместе с проверкой запуска контекста прошло 10 тестов.

Дополнительно формы проверены в браузере: добавление студента, создание группы, изменение её курса и удаление. Сохранение студента после принудительной остановки и повторного запуска файловой H2 проверено отдельно.
