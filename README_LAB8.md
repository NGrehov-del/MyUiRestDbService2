# Лабораторная работа 8

## Что сделано

В существующее приложение добавлен Spring Security. Реализованы публичная главная страница, регистрация, вход по email и паролю, выход, защищённые списки студентов и учебных групп, а также список зарегистрированных пользователей.

Созданы сущности User и Role со связью многие ко многим, таблицы USERS, ROLES и USERS_ROLES, репозитории, UserDto, UserService, UserServiceImpl, CustomUserDetailsService, WebSecurityConfig, MvcConfig и SecurityController. Репозитории студентов и групп перенесены из dao в repository.

Пароли хешируются BCrypt. В базе не хранится исходный пароль; список пользователей не показывает ни пароль, ни его хеш. Email приводится к нижнему регистру, повторная регистрация того же адреса отклоняется. Невалидные поля возвращаются на форму с пояснениями.

Роль при регистрации — ROLE_ADMIN, как в учебном примере методички. Список /users, Actuator и H2-консоль доступны только этой роли. Студенты и группы доступны вошедшему пользователю. До регистрации нет заранее заданного пользователя и нет общего пароля администратора — создайте свою учётную запись.

В присланном проекте используется Spring Boot 4.1.1 и Java 17. Старый синтаксис настройки Security из методички для Spring Boot 2.7 адаптирован к используемой версии. Циклические зависимости не нужны. CSRF-защита форм сохранена; токены добавляются Thymeleaf автоматически. Выход и удаление записей выполняются POST-формами. Исключение CSRF сделано только для защищённой H2-консоли, которой необходима собственная форма входа.

Приложение слушает 127.0.0.1:8080 и предназначено для локальной учебной проверки. Таблицы создаются Hibernate при первом старте, ddl-auto=update сохраняет данные при следующих запусках. Старый schema.sql лабораторной 7 не выполняется, так как spring.sql.init.mode=never.

## Запуск

1. Остановите приложение лабораторной 7 или 6, если оно занимает порт 8080.
2. Откройте проект из папки ЛабораторнаяРабота8. Нужен вложенный каталог MyUiRestDbService с pom.xml.
3. При необходимости добавьте pom.xml как Maven-проект, выберите JDK 17 и дождитесь загрузки зависимостей.
4. Запустите MyUiRestDbServiceApplication кнопкой возле main.
5. Откройте http://localhost:8080/index.
6. Нажмите «Регистрация», введите имя, фамилию, email и пароль длиной от 6 символов. После успешного сохранения нажмите «Войти».
7. Введите тот же email и пароль. После входа откроется /users со списком пользователей. В меню появятся «Студенты», «Учебные группы» и «Выйти».

Вводите учебные данные. Email нужен как логин; отправка писем и проверка существования почтового ящика не выполняются. Пароль ограничен 72 байтами UTF-8 из-за используемого BCrypt; для латинских символов это не более 72 символов.

Working directory конфигурации запуска должен указывать на папку этого проекта с pom.xml, чтобы относительная база testdb/students.mv.db относилась именно к лабораторной 8.

## Проверка по шагам

1. До входа откройте http://localhost:8080/list. Должно произойти перенаправление на страницу входа.
2. Зарегистрируйте пользователя. Ожидается сообщение об успешной регистрации.
3. Попробуйте повторить регистрацию с тем же email. Ожидается ошибка у поля email.
4. На странице входа введите неверный пароль. Ожидается «Неверный email или пароль».
5. Войдите с правильным паролем. Должен открыться список пользователей без паролей.
6. Через меню откройте студентов и проверьте добавление, изменение и удаление. Учебные группы лабораторной 7 также сохранены.
7. Нажмите «Выйти». Должно появиться сообщение о выходе. Повторное открытие /list должно снова направить на вход.
8. Перезапустите приложение. Пользователь, его пароль и записи базы должны сохраниться. Войдите повторно.

Не отправляйте старые POST-запросы из Postman без CSRF-токена: теперь для изменения данных нужны авторизация, сессионная cookie и токен формы. Для этой лабораторной удобнее выполнять ручную проверку в браузере.

## Просмотр БД

После входа под зарегистрированным пользователем откройте http://localhost:8080/h2-console/.

JDBC URL: jdbc:h2:file:./testdb/students

Имя пользователя базы: sa. Пароль базы пустой. Это отдельные реквизиты H2, а не email и пароль веб-приложения.

```sql
SELECT ID, NAME, EMAIL FROM USERS;
SELECT * FROM ROLES;
SELECT * FROM USERS_ROLES;
SELECT * FROM STUDENTS;
```

Если нужен снимок хешированного пароля, выполните SELECT ID, EMAIL, PASSWORD FROM USERS: в PASSWORD должен быть BCrypt-хеш, а не исходный пароль. При работе через DBeaver сначала остановите приложение и подключитесь к тому же файлу H2.

## Тесты

SecurityIntegrationTest проверяет регистрацию, хеширование, роль, дубликат email, неверные поля, CSRF, неверный пароль, список пользователей без паролей, выход, запрет списка для ROLE_USER, CRUD после входа и доступ к Actuator только администратору. Вместе с проверкой запуска контекста выполнено 18 тестов.

Запуск: откройте src/test/java/ru/itlearn/MyUiRestDbService/SecurityIntegrationTest.java → зелёная кнопка возле класса → Run. Для всех тестов используйте Maven → Lifecycle → test. Они работают с отдельной H2 в памяти и не меняют ваши пользовательские данные.
